# 任务模板维护说明

`task-template.md` 是新生成任务文件的模板来源。每个任务文件都会包含生成时的模板全文和模板哈希；运行开始后不自行同步其它版本；用户明确授权迁移时按 SKILL 保存快照并记录修订。

## 来源

本 skill 于 2026-11-06 从 `cyclic-task-prompt`（仓库 `sskyy/cycle-runner`，提交 `50c5287`，模板 `protocol-template.md` sha256 前 12 位 `448e4e388c66`）派生。`cycle.mjs`、`cycle.test.mjs`、`references/project-profile-schema.md` 为原样副本；模板的固定约束、概念、设计文档要求、评审条件、缺陷卡片与机制词表沿用其定义；角色段按主从编排重写。两个 skill 互不修改，各自维护。

## 当前设计

一个常驻主 agent 加三种子 agent。主 agent 做立项与再设计、派发、回答工作者的问题、执行判定者的结论；工作者按步实现并提交检查点；验收者每圈新起、在干净克隆上独立复验；独立评审每次新起，审设计与复评整个任务。runner 只记事实。

与 `cyclic-task-prompt` 相比的改动及依据（依据来自 mesh 的 cyclic 运行记录与 Iris `docs/skeleton-copy` 的运行，2026-11-06 分析）：

| 改动 | 防止的失败 | 证据 |
|---|---|---|
| 立项与评审的会话切换、每轮重读 54 KB 模板与 23 KB 画像、每轮交接提交，改为主 agent 常驻与子 agent 派发 | 每轮 10–15 分钟的传输开销；GUI 启动链故障 | skeleton-copy 76 轮，传输开销估计约 15 小时（提交间隔推算，单运行） |
| 工作者可以向主 agent 提问 | 工作轮把写给验收的规则当作自己的停止理由而提前结束 | skeleton-copy 工作轮 13、15、17 用时为预计的 1/4–1/8，主要预期未命中（单运行，cyclic 维护记录 11-02） |
| 主 agent 不审自己的设计、不对自己的计划判停止；这些交独立评审（固定约束 2、6） | 评判自己提出的方法时发现不了问题 | skeleton-copy 复评 c12、c14、c16 评判自己方法时三次没有发现问题（单运行，11-02）；mesh 裁决座位 110 轮采纳 108 轮（多运行，10-12） |
| 验收与评审结论对主 agent 有约束力（固定约束 3） | 作者座位绕过判定者 | mesh 裁决推翻评审的通过（issue-884 第 11 轮、issue-957 第 13 轮，多运行，10-12）当时未限制；在主从结构里这是唯一能绕过判定者的口子 |
| 工作者按步起、每步检查点提交；验收者每圈新起（固定约束 7） | 长会话中途丢失工作；常驻判定者对自己旧结论有立场 | skeleton-copy cycle 28 工作轮 4 小时无检查点提交，额度耗尽后全部丢失（单运行）；cyclic 10-13 的跨轮改判 |
| 派发前状态落盘、子 agent 结论写文件、主会话恢复入口（固定约束 8） | 主会话中断后无人知道下一步 | skeleton-copy 主会话因额度耗尽中断两次（cycle 10 前后、cycle 28），靠状态头与文件接续（单运行） |
| brief 只含路径、角色、编号 | 子 agent 把派发者的假设确认回来 | cyclic 10-18 按 7 个子 agent 推演写入的计数层在三次真实运行中出错并于 10-25 删除（多运行） |
| 验收的范围写为交接接口：受影响部分加风险抽查，完整核验只在 `待审` 且每圈一次 | 每圈完整核验 45–70 分钟跑两到三遍 | skeleton-copy 验收记录（单运行）；同一规则在 cyclic 模板里是方法，验收者没有执行 |
| 运行记录每条带模型、用量、活动墙钟 | 两种会话组织的效率无法实测比较 | cyclic 运行只记墙钟，issue-supervisor 记美元；没有按轮的 token 或费用 |
| 生成步骤增加「任务切片的原则」：普查类按能力类别分批，零残余不作完成条件 | B/C 类全称目标不收敛 | mesh 1401、1542、1670、1496 全部是开放人口上造判定器的任务（多运行，10-18）；skeleton-copy M-04 占 cycle 9–39 |
| 不限定执行环境，不往仓库放会话启动文件 | 启动链依赖桌面 GUI 与辅助功能权限 | cyclic 的 11 个后端全部是 GUI 自动化（研究报告 05 §4） |
| 方法段每条只保留目的与做法，例子移入本文件 | 任务文件篇幅是每个子 agent 的固定阅读成本 | 这是有意的取舍：11-02 的记录表明只写规则不写理由会被按字面执行，所以目的保留、例子删去；效果由真实运行检验 |

未改：准入分类 A/B/C、价值判断、设计七部分、评审四条件、状态头九字段、账本类别、快照路径、缺陷卡片与机制词表、资源等待规则、`d = 3` 协议失败。

## 局限

- 截至 2026-11-06 本 skill 没有真实运行。上表的证据来自 cyclic 的运行，用于推断，不是本设计的验证。
- 预期的加速来自传输开销与提前结束的消除，估计占原墙钟的一到两成；完整核验时长、额度停摆与任务切片方式不由本 skill 决定。
- 主 agent 的上下文随任务增长；多天任务里它仍须依赖文件而不是自己的记忆，固定约束 8 为此而设，效果待验证。
- 双工对话与续用依赖执行环境的能力；降级方式（写问题进运行记录、重新起工作者）会增加一轮。

## 维护要求

1. 使用多个任务的可核对复盘证据评估模板，不因单个任务增加全局规则。
2. 优先删除无助于产品推进的流程要求。
3. 新规则必须说明它防止的具体失败，并说明为何不能由项目原有测试、角色职责或 runner 解决。
4. 固定约束与交接接口不改为建议；方法写目的与做法，例子只进本文件。
5. 修改模板后更新本文件；任务文件中的模板哈希用于识别运行版本。
6. runner 与 `cyclic-task-prompt` 的接口保持一致；runner 有行为变化时同步两边或在本文件写明分叉原因。
