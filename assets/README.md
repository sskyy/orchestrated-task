# 任务模板维护说明

`task-template.md` 是新生成任务文件的模板来源。每个任务文件都会包含生成时的模板全文和模板哈希；运行开始后不自行同步其它版本；用户明确授权迁移时按 SKILL 保存快照并记录修订。

## 来源

本 skill 于 2026-11-06 从 `cyclic-task-prompt`（仓库 `sskyy/cycle-runner`，提交 `50c5287`，模板 `protocol-template.md` sha256 前 12 位 `448e4e388c66`）派生。`cycle.mjs`、`cycle.test.mjs`、`references/project-profile-schema.md` 为原样副本；模板的固定约束、概念、设计文档要求、评审条件、缺陷卡片与机制词表沿用其定义；角色段按主从编排重写。两个 skill 互不修改，各自维护。

## 当前设计

一个常驻主 agent 加三种子 agent。主 agent 做立项与再设计、派发、回答工作者的问题、执行判定者的结论；工作者按步实现并提交检查点；验收者每圈新起、在干净克隆上独立复验；独立评审每次新起，审设计与复评整个任务。runner 只记事实。

与 `cyclic-task-prompt` 相比的改动及依据（依据来自 mesh 的 cyclic 运行记录与 Iris `docs/skeleton-copy` 的运行，2026-11-06 分析）：

| 改动 | 防止的失败 | 证据 |
|---|---|---|
| 立项与评审的会话切换、每轮重读 54 KB 模板与 23 KB 画像、每轮交接提交，改为主 agent 常驻与子 agent 派发 | 每轮 10–15 分钟的传输开销；GUI 启动链故障 | skeleton-copy 76 轮，传输开销估计约 15 小时（提交间隔推算，单运行） |
| 工作者可以向主 agent 提问 | 工作轮把写给验收的规则当作自己的停止理由而提前结束 | skeleton-copy 工作轮 13、15、17 用时为预计的 1/4–1/8，主要预期未命中（单运行，cyclic 维护记录 11-02） |
| 主 agent 不审自己的设计、不对自己的计划判停止；这些交独立评审（固定约束 2、6） | 评判自己提出的方法时发现不了问题 | skeleton-copy 复评 c12、c14、c16 评判自己方法时三次没有发现问题（单运行，11-02）；mesh 裁决座位 110 轮采纳 108 轮（多运行，10-12） |
| 验收与评审结论对主 agent 有约束力（固定约束 3） | 作者座位绕过判定者 | mesh 裁决推翻评审的通过（issue-884 第 11 轮、issue-957 第 13 轮，多运行，10-12）当时未限制；在主从结构里这是唯一能绕过判定者的口子 |
| 工作者按步起、每步检查点提交；验收者每圈新起（固定约束 7） | 长会话中途丢失工作；常驻判定者对自己旧结论有立场 | skeleton-copy cycle 28 工作轮 4 小时无检查点提交，额度耗尽后全部丢失（单运行）；cyclic 10-13 的跨轮改判 |
| 派发前状态落盘、子 agent 结论写文件、主会话恢复入口（固定约束 8） | 主会话中断后无人知道下一步 | skeleton-copy 主会话因额度耗尽中断两次（cycle 10 前后、cycle 28），靠状态头与文件接续（单运行） |
| brief 只含路径、角色、编号 | 子 agent 把派发者的假设确认回来 | cyclic 10-18 按 7 个子 agent 推演写入的计数层在三次真实运行中出错并于 10-25 删除（多运行） |
| 验收的范围写为交接接口：受影响部分加风险抽查，完整核验只在 `待审` 且每圈一次 | 每圈完整核验 45–70 分钟跑两到三遍 | skeleton-copy 验收记录（单运行）；同一规则在 cyclic 模板里是方法，验收者没有执行 |
| 运行记录每条带模型、用量、活动墙钟 | 两种会话组织的效率无法实测比较 | cyclic 运行只记墙钟，issue-supervisor 记美元；没有按轮的 token 或费用 |
| 生成步骤增加「任务切片的原则」：普查类按能力类别分批，零残余不作完成条件 | B/C 类全称目标不收敛 | mesh 1401、1542、1670、1496 全部是开放人口上造判定器的任务（多运行，10-18）；skeleton-copy M-04 占 cycle 9–39 |
| 不限定执行环境，不往仓库放会话启动文件 | 启动链依赖桌面 GUI 与辅助功能权限 | cyclic 的 11 个后端全部是 GUI 自动化（研究报告 05 §4） |
| 方法段每条只保留目的与做法，例子移入本文件 | 任务文件篇幅是每个子 agent 的固定阅读成本 | 这是有意的取舍：11-02 的记录表明只写规则不写理由会被按字面执行，所以目的保留、例子删去；效果由真实运行检验 |

## 2026-11-07 修订（第一次真实运行之后）

依据 Iris `docs/skeleton-copy` 以本 skill 运行的 cycle 43–62（见「局限」），用户于 2026-11-07 授权修订。原则：写死的只保留两类内容，谁判谁（独立性）与状态落盘（可恢复性），因为这两类失败不随模型变强而消失；关于判断的内容写目的与做法，不写计数器或触发条件，以免在模型变强时成为束缚。改动全部在模板的方法段、复评段、验收者段与对话边界；固定约束、runner 与交接接口未改。

| 改动 | 防止的失败 | 证据 | 为何不能由既有角色、测试或 runner 解决 |
|---|---|---|---|
| 复评的首要问题改为两问：完成条件是否仍能以有界的工作达成；按它继续是否仍是合理投入。原问题「是否存在值得继续的下一步」删去 | 对开放人口上的判定器，更窄的下一步永远存在，原问题总能得到「是」 | 复评 c54、c56、c58 都亲自重跑了验收的变体、看到同一机制累计多张缺陷卡片与 `C` 连续后移，仍判「继续」并各收紧一次判定器规则；c61 以同样的事实判定完成条件无上界并把开放残余登记为独立事项。事实在 c54 时已全部存在 | 这是复评提问方向的问题，验收者与主 agent 都无权改完成条件 |
| 上一次复评的处置方式与预先登记只约束主 agent，不限定下一次复评的提问范围 | 每位新起的评审继承上一位划定的问题，四次复评都在回答同一个被错误设定的问题 | 设计 §7 的预先登记链 c52→c54→c56→c58→c59-Q→c61 | 预先登记是评审自己写的，没有规则说明它约束谁 |
| 「复现与结构性修改」的标准删去「未列出的写法加回时变红」作为完成条件；验收者步骤 2 区分「掩盖了当前树成员」与「没有掩盖任何成员」的静默放过，后者记录并交独立评审处置 | 验收者每圈自构几十个写法，总能找到静默放过的，完成条件没有终点 | 验收 cycle 53、55、57、60 各自构 9–53 个写法，每次 4–9 个静默放过，M-06 第 2 步续了五次，同一机制七张缺陷卡片 | 验收者按原文执行原标准，执行正确；错的是标准本身 |
| 估算段把「预计结束圈连续两次后移」从失效条件改为供判断的信息，并列出要读的位置 | 把迹象写成条件，模型要么机械触发要么绕过；写成信息，由评审判断 | `C` 从 49 后移到 63 共九次，剩余圈数六次不减；主 agent 在 c52 自行引用这条判断请求复评，之后又后移四次 | 信息已在设计 §7 与验收记录中，不需要 runner 另行计算（计算会成为第二个写者） |
| 对话边界增加：同一步内多个触及冻结项的问题交同一次在途的独立评审续答，算同一次调用 | 每个问题新起一次评审，成本 20–25 分钟 | 复评 c59-Q 续答工作者 cycle 59 的 Q3、Q4 各约 4–7 分钟，与新起评审的 20–25 分钟对照 | 固定约束 7 的「每次调用新起」没有定义一次调用的范围 |
| 删去「子 agent 不读其它角色段」 | 规则被无视而无损失，留着只训练子 agent 忽略规则 | 验收 c45、c47、c51、c53 四次通读全部角色段，判断不受影响 | 阅读范围靠文字无法约束 |

撤回的方案：按被拒次数、`C` 后移次数或换量次数触发动作的计数器。理由见上，用户于 2026-11-07 否决了计数器式的规则。

## 2026-11-08 修订（两个任务之后）

依据 Iris `docs/takeover-path`（已完成，15 圈，12 小时）与 `docs/clock-seam`（前 9 圈）的运行记录，用户于 2026-11-08 授权修订，目标是缩短每圈时间。原则不变：只改方法段与角色段的做法，写目的与做法，数值留给项目画像。

| 改动 | 防止的失败 | 证据 | 为何不能由既有角色、测试或 runner 解决 |
|---|---|---|---|
| 「验收的范围」：本步没有改动可执行代码时，验收不建干净环境、不运行测试道；工作者在检查点只运行受影响的道，完整命令集只在准备标 `待审` 时运行一次 | 每圈 15–32 分钟的干净环境与测试道运行对只改文档与登记的步不产生信息；工作者每个检查点运行完整命令集 | 两个任务验收占活动时间约三分之一，其中固定部分约 30 分钟；takeover-path 与 clock-seam 的验收记录 | 验收者按原文倾向保守；原文没有区分步的内容 |
| 「步的大小」：一步的预期返工成本低于一次验收的固定成本时与相邻步合并；拆步的理由是失败时的返工代价 | 为便于逐项核对而拆出的小步，各自付一次验收固定成本 | 同上；cyclic 时期 3–8 小时的工作轮配 2–4.5 小时的验收，说明验收可变部分随步长增长，合并的收益只在固定部分 | 步的划分由评审与验收者写，原文没有给合并的依据 |
| 工作者步骤 3：等待回答期间继续不依赖该回答的完成条件 | 工作者等待复评答复时闲置 | takeover-path 第 2a 步工作者等待约 25 分钟；clock-seam 第 2a-1 步工作者等待期间继续其它条件 | 原文只写「等待回答」 |
| 「估算」：单位成本优先取项目画像或上一个任务终止总结的实测值；终止总结增加各角色的实测单位成本 | 立项估算系统性偏低，`C` 在运行期反复修正 | takeover-path `C` 10 → 16（实际 15）；clock-seam 18 → 32 | 没有位置承载跨任务的实测值；runner 只记事实 |
| SKILL 运行要点：只在派发之后与处理结论之后向用户报告 | 主 agent 对子 agent 的每条中间通知逐条回复 | skeleton-copy 期间主 agent 对一次验收的十余条中间通知逐条回复，用户指出 | 执行要点，不属任务文件 |

项目特定的内容（Iris 的单位成本数值、自查的缺陷形态）写进 `docs/agent-project-profile.md`，不进模板。

未改：准入分类 A/B/C、价值判断、设计七部分、评审四条件、状态头九字段、账本类别、快照路径、缺陷卡片与机制词表、资源等待规则、`d = 3` 协议失败。

## 局限与已有的运行证据

- 第一次真实运行：Iris `docs/skeleton-copy`，2026-11-06 23:08 从 cyclic-task-prompt 迁移（验收 cycle 42 之后），2026-11-07 21:49 以「已完成」结束，cycle 43–63，6/6 里程碑，零停摆。按圈的效率成立：验收一圈 20–95 分钟（cyclic 同任务为 1 小时 45 分到 4 小时 30 分），工作一步 50 分钟到 2 小时 45 分，复评 10–40 分钟，主 agent 派发数分钟；每圈约 25–80 万 token。按里程碑的效率只在前半段成立：cycle 43–52 收口 M-05 并完成 M-06 两步；cycle 53–62 全部花在 M-06 第 2 步的一个判定器上，原因见「2026-11-07 修订」。
- 加速的主项是验收范围收窄与步变小，两者在 cyclic 模板里是方法而未被执行，本模板把它们写成交接接口；会话组织本身的贡献约一到两成，与派生时的估计一致。完整核验时长与任务切片方式仍不由本 skill 决定。

- 双工对话与续用在该运行的执行环境中可用：工作者提问六次，工作者续用两次，评审续答两次。降级方式（写问题进运行记录、重新起工作者）未经真实运行检验。
- 修订后的复评提问在 takeover-path 与 clock-seam 的六次运行期复评中都被逐条回答，其中两次据此改写了不可达的口径；验收者在 clock-seam 第 8 圈把判定边界登记为验证缺口交独立评审而不是拒绝。2026-11-08 修订的做法尚未经真实运行检验。

## 维护要求

1. 使用多个任务的可核对复盘证据评估模板，不因单个任务增加全局规则。
2. 优先删除无助于产品推进的流程要求。
3. 新规则必须说明它防止的具体失败，并说明为何不能由项目原有测试、角色职责或 runner 解决。
4. 固定约束与交接接口不改为建议；方法写目的与做法，例子只进本文件。
5. 修改模板后更新本文件；任务文件中的模板哈希用于识别运行版本。
6. runner 与 `cyclic-task-prompt` 的接口保持一致；runner 有行为变化时同步两边或在本文件写明分叉原因。
